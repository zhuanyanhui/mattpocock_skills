# 通用语言

从当前对话中提取并规范领域术语，形成一致的词汇表，保存到本地文件。

## 流程

1. **扫描对话**，查找与领域相关的名词、动词和概念
2. **识别问题**：
   - 同一个词用于不同概念（歧义）
   - 不同词用于同一个概念（同义词）
   - 模糊或过载的术语
3. **提出规范词汇表**，给出有倾向性的术语选择
4. **写入工作目录下的 `UBIQUITOUS_LANGUAGE.md`**，使用以下格式
5. **在对话中输出摘要**

## 输出格式

编写具有以下结构的 `UBIQUITOUS_LANGUAGE.md` 文件：

```md
# 通用语言

## 订单生命周期

| 术语         | 定义                                   | 需要避免的别名               |
| ----------- | -------------------------------------- | --------------------------- |
| **订单**    | 客户购买一个或多个商品的请求             | 购买、交易                   |
| **发票**    | 在交付后发送给客户的付款请求             | 账单、支付请求               |

## 人员

| 术语         | 定义                                   | 需要避免的别名               |
| ------------ | -------------------------------------- | --------------------------- |
| **客户**     | 下单的个人或组织                         | 客户方、买家、账户            |
| **用户**     | 系统中的认证身份                         | 登录名、账户                 |

## 关系

- 一张**发票**属于且仅属于一个**客户**
- 一个**订单**产生一个或多个**发票**

## 示例对话

> **开发者：**"当**客户**下了一个**订单**，我们会立即创建**发票**吗？"
> **领域专家：**"不——**发票**只在**履约**确认后生成。如果商品分多个**包裹**运输，一个**订单**可以产生多张**发票**。"
> **开发者：**"所以如果**包裹**在发货前被取消，就不存在对应的**发票**？"
> **领域专家：**"没错。**发票**的生命周期与**履约**绑定，而不是与**订单**绑定。"

## 标记的歧义

- "account" 被同时用来表示**客户**和**用户**——这是两个不同的概念：**客户**下单，而**用户**是一个认证身份，可能代表也可能不代表一个**客户**。
```

## 规则

- **要有倾向性。**当同一个概念存在多个词时，选择最佳的一个，将其他列为需要避免的别名。
- **显式标记冲突。**如果一个术语在对话中使用有歧义，在"标记的歧义"部分明确指出，并给出清晰的建议。
- **只包含领域专家相关的术语。**跳过模块或类的名称，除非它们在领域语言中有意义。
- **保持定义简洁。**最多一句话。定义它**是什么**，而不是它**做什么**。
- **展示关系。**使用粗体术语名称，在关系明显时标明基数。
- **只包含领域术语。**跳过通用编程概念（数组、函数、端点），除非它们具有领域特定含义。
- **当自然聚类出现时，将术语分组到多个表格中**（例如按子领域、生命周期或参与者）。每个组有自己的标题和表格。如果所有术语属于一个单一的凝聚领域，一个表格就够了——不要强行分组。
- **编写示例对话。**开发者和领域专家之间的一段简短对话（3-5 轮），展示术语如何自然地交互。对话应澄清相关概念之间的边界，并展示术语被精确使用。

## 示例对话

> **开发者：**"没有 Docker 我怎么测试**同步服务**？"

> **领域专家：**"提供**文件系统层**而不是 **Docker 层**。它实现了相同的 **Sandbox 服务**接口，但使用本地目录作为**沙箱**。"

> **开发者：**"所以 **sync-in** 仍然会创建一个**包**然后解包？"

> **领域专家：**"没错。**同步服务**不知道它在和哪个层对话。它调用 `exec` 和 `copyIn`——**文件系统层**只是把它们作为本地 shell 命令运行。"

</example>

## 重新运行

当在同一对话中再次调用时：

1. 读取现有的 `UBIQUITOUS_LANGUAGE.md`
2. 整合后续讨论中的新术语
3. 如果理解已演进，更新定义
4. 重新标记任何新的歧义
5. 重写示例对话以包含新术语
