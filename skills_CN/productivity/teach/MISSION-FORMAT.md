# MISSION.md 格式

`MISSION.md` 位于工作空间根目录。它记录了用户学习这个主题的**原因**。每一个教学决策——接下来教什么、呈现哪些资源、设计哪些练习——都应该追溯到这份文档。

## 模板

```md
# 任务：{主题}

## 为什么
{1-3 句话。用户追求的具体现实目标是什么？当用户拥有这项技能后，他们的生活或工作会发生什么改变？避免"理解 X"这类抽象表述——追求底层的结果。}

## 成功的样子
- {用户将能做到的一个具体的、可观察的事情}
- {另一个具体的事情}
- {…}

## 约束条件
- {时间、预算、已有承诺、学习偏好、任何限制方法的因素}

## 超范围
- {用户明确表示现在不想涉及的相邻主题——保护最近发展区}
```

## 规则

- **每个工作空间只有一个任务。** 如果用户想学两个不相关的东西，那是两个工作空间。
- **具体胜于抽象。** "十月前半程跑完半程马拉松"胜过"变得更健康"。"为我的团队发布一个 Rust CLI"胜过"学习 Rust"。
- **对模糊性进行追问。** 如果用户无法说出为什么，在写任何东西之前先采访他们。一个糟糕的任务比没有任务更糟。
- **当现实变化时修订。** 任务会变化。当用户的目标改变时，更新这份文件——不要留过时的任务来指导未来的会话。
- **保持简短。** 如果 `MISSION.md` 超过一屏，它就不再是指南针，而变成了一份计划。
