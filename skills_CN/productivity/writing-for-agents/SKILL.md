编写 agent 消费的任何文档的参考——skill、`AGENTS.md`/`CLAUDE.md`、通过指针到达的文档。打包方式不同，但写法相同：同样的控制点使每个文档可预测——agent 在每次运行时遵循相同的*过程*，而不是产出相同的输出。

当你编写的文档是 skill 时，阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md) 了解 frontmatter、调用选择和路由器 skill。

## Context pointers（上下文指针）

**context pointer（上下文指针）** 是 agent 上下文中持有的一种引用，它指向某个上下文之外的材料并编码了何时到达它的条件。skill 的描述就是一个；`AGENTS.md` 中命名某个文档的一行也是同样的对象。指针的*措辞*（而非它的目标）决定了 agent 何时到达该材料——以及可靠性如何。一个必不可少的目标放在措辞薄弱的指针后面是一个**variance bug（方差缺陷）**：先锐化措辞，仅在锐化无效时才内联材料。

指针做两件事——说明材料是什么，以及列出应触发访问它的**branches（分支）**（分支是文档处理的不同情况，因此不同运行会走不同路径）。always-loaded（始终加载）指针中的每个词在每个 turn 都花销上下文，因此它比正文更值得严格裁剪：

- **前置 leading word（引导词）** —— 指针正是在前端发挥触发作用的。
- **每个分支一个触发。** 重命名同一分支的同义词只是同一个分支写了两次；合并它们，只保留真正不同的分支。
- **删除正文已经携带的身份信息。**

## The two loads（两种负担）

你添加的每个文档和指针都会消耗两种预算之一：

- **Context load（上下文负担）** —— 始终加载的材料对 agent 窗口的开销：一行 `AGENTS.md`、一个 skill 描述、任何在每个 turn 都存在于上下文中的东西，无论是否触发都在消耗 token 和注意力。
- **Cognitive load（认知负担）** —— 对人的开销：哪些文档存在，以及何时使用每个文档。人是索引。这不是要最小化的成本——它是人类控制权的代价；在人类判断重要的地方花销它，在不重要的地方移除它。

仅通过指针访问的材料以指针自身一行为代价逃离 context load；根本没有指针的材料则完全依赖 cognitive load。

## Information hierarchy（信息层次结构）

文档由两种内容类型构建——**steps（步骤）**（agent 执行的有序动作）和 **reference（参考）**（按需查阅的定义、规则、事实）——它们自由混合：全是步骤（一份食谱），全是参考（代码审查的规则、本 skill），或两者兼有。核心决策是每个部分位于**信息层次结构**的哪个位置，这是一个按 agent 需要材料的紧急程度排序的阶梯：

1. **In-file step（文件内步骤）** —— 主层：agent 按顺序做什么。
2. **In-file reference（文件内参考）** —— 按需查阅。通常是合理的扁平同级集（审查的每条规则在同一级）——这是一种好的安排，不是坏味道。
3. **Disclosed reference（披露式参考）** —— 推入单独文件，通过 context pointer（上下文指针）访问，仅在指针触发时加载。通过同目录的兄弟文件，延伸到任何地方都存在的外部参考，任何文档都可以指向它。

推得太少，顶部膨胀；推得太多，你隐藏了 agent 实际需要的材料。这种张力就是整个决策。

**Progressive disclosure（渐进式披露）** 是沿阶梯下移的动作——移出主文件，放在指针后面——以便顶部保持可读。这主要不是 token 优化：它是保护层次结构的方式。分支是最干净的披露测试：内联每个分支都需要的东西，把只有部分分支到达的内容推到指针后面。当文档有步骤时，应该被披露的文件内参考会掩埋它们，把关注它们变成抛硬币——这是一个 variance lever（方差控制点），不仅仅是可读性问题。

**Co-location（同址放置）** 是文件内的伴侣：阶梯决定一块内容*坐在多深*，同址放置决定*到了那里后什么坐在它旁边*。把一个概念的定义、规则和注意事项放在一个标题下，而不是散落各处，这样阅读一部分就能带着它的邻居一起。测试标准：文档应该读起来像是为 agent 写的文档——分组材料读起来像；散落材料读起来不像。（区别于重复：重复是在两个地方重复同一含义；散落是将一个含义碎片化到多处。）

**Sprawl（蔓延）** 是这里的失败模式：一个文档仅仅太长了，即使每行都是活跃的、唯一的。注意力在多余内容中稀释，每多一行就是多一个需要保持相关的东西。治疗方法是阶梯：把参考披露到指针后面，按分支或序列拆分，使每条路径只携带它需要的东西。

## Steps and completion criteria（步骤与完成标准）

每个步骤都以**completion criterion（完成标准）**结束——告诉 agent 工作已完成的条件。两个属性使其成为控制点：

- **Clarity（清晰度）** —— agent 能区分完成与未完成吗？模糊的边界（"达到理解"）会招致**premature completion（过早完成）**：在步骤真正完成之前就结束，注意力滑向*已完成*。仍然在前的可见步骤——**post-completion steps（完成后步骤）**——提供拉力；标准的清晰度是阻力。按顺序防御：**先锐化边界**（局部的、便宜的）；仅当它不可简化地模糊*且*你观察到仓促行为时，才通过拆分序列来隐藏后续步骤——并且隐藏只在真正的上下文边界处有效（交接或子 agent 调度；内联调用会使后续步骤保留在上下文中，什么都清理不掉）。
- **Demand（要求强度）** —— 它要求多少。"每个修改的模型都已计入"强制彻底工作，而"生成变更列表"则不会。Demand 驱动**legwork（深入查找）**——agent 在工作中进行的挖掘，潜伏在措辞中而非写为自己独立的步骤——而且它不限于步骤："每条规则已应用"绑定一组扁平参考，就像"每步已完成"绑定一个序列，这就是为什么纯参考文档仍然携带穷尽标准。

最强的标准既可检查又穷尽。

## When to split（何时拆分）

将一个文档拆分为两个会消耗两种负担之一，所以仅在切分值得时才拆分：

- **By sequence（按序列）** —— 在一连串步骤中拆分，当完成后步骤引诱 agent 仓促处理前面的步骤时。将它们排除在视野之外可以驱动对当前任务的更多深入工作。警惕反向操作：合并序列会将每个步骤的后续步骤暴露给后续内容，招致过早完成。
- **By invocation（按调用）** —— skill 特有的：参见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## Leading words（引导词）

**leading word（引导词）** 是一个紧凑的概念，已经存在于模型的预训练中，agent 在运行文档时用它来思考（_lesson_、_fog of war_、_tracer bullets_）。作为 token 重复，从不作为句子，它累积了一个分布式定义，并在最少的 token 中锚定了整个行为区域，通过招募模型已经持有的先验。如果你清楚定义，自创词也有效，但生造的词不招募任何先验——你花在定义 token 上的代价是预训练词免费提供的；优先选择已有的词。

它在两处锚定。在正文中，_执行_：agent 每次出现该词时都会采取相同行为；在扁平参考中，它将注意力聚焦在一类需要寻找的事物上。在指针中，_调用_：当同一个词存在于你的 prompt、文档和代码库中时，agent 会将这种共享语言与材料链接起来，更可靠地到达它。

积极寻找用引导词进行重构的机会。在三个地方明确拼写的三重奏、指针花一个句子暗示一个想法——每段都是渴望折叠成单个 token 的段落：

- "fast, deterministic, low-overhead" → _tight_（一个 _tight_ 循环）。
- "a loop you believe in" → _red_ —— 模糊的门变成二元可观察状态（循环对 bug 变 _red_，或不变）。

你赢了两次：更少的 token，以及更锋利的钩子让 agent 挂上它的思考。假设每个文档都携带着引导词可以退休的重述——去找到它们。

**Negation（否定）** 是这个控制点旁边的失败模式：通过禁令来引导会把禁止的行为拖入上下文，使它*更*可用，而不是更少。*不要想大象*，结果全是大象；否定是一个弱修饰符，被强烈激活的概念会覆盖它，所以禁令半读起来像做那件事的指令。Prompt 应该用**正面**——陈述目标行为（"写单行注释"），这样被禁止的行为永远不会被提及。禁令只有在无法正面表达的硬防护栏时才有资格存在；即便如此，也要与正面目标配对，使注意力落在该做什么上。

## Pruning（裁剪）

- 将每个含义保持在**single source of truth（单一事实来源）**：一个权威位置，所以更改行为只需一处编辑。**Duplication（重复）** —— 同一含义出现在多个位置 —— 增加维护成本和 token，并使含义在阶梯上的突出程度超过其实际等级。（这是 leading word 的意外反面：leading word 有意识地重复 token，而非含义。）
- **Environment（环境）** 也是事实来源——`package.json` 脚本、配置文件、目录布局、`--help` 输出——而重述它的文档是一个**cache（缓存）**：一份查找的拷贝，仅在查找昂贵时才赚回它的加载成本。缓存 agent 无法通过查看找到的东西：未写明的惯例、某个选择背后的原因、没有配置承认的陷阱。把单文件、单命令的查找留给环境，在那里它们不会过期。
- 检查每行的**相关性**：它是否仍然与文档的作用有关？一行从不涉及任务（单纯的阐述，或应该被披露的分支）就会失去相关性，或者随着它描述的行为或世界变化而过时。较短的文档更容易保持相关性。没有裁剪纪律的话，默认命运是**sediment（沉积物）**：过时的层堆积起来，因为添加感觉安全而删除感觉危险，直到你必须从中挖出仍然活跃的内容。
- 逐句搜寻**no-ops（无操作）**：模型默认已经遵守的指令白花了加载成本来说空话。测试标准——它相对于默认值改变了行为吗？——是模型相关的，而非读者相关的：两个人对某个 no-op 有分歧，实际上是对默认值有分歧，通过运行文档而非辩论来解决。当一行失败时，删除整行而不是从中删减词汇。这个测试也用于给 leading word 打分：太弱而无法胜过默认值的词（agent 已经相当彻底时说 _be thorough_）是 no-op，修复方法是用更强的词（_relentless_），而非不同技术。
