# 向导

**向导**（wizard）是一个 bash 脚本，它逐步引导人类完成手动流程——这些流程手动操作很繁琐，每次重新向 AI 解释也很繁琐。它打开每个 URL，确切地说明要点击和复制什么，捕获值，将它们写入正确位置（`.env`、GitHub 密钥），在每个阶段进行确认，并显示剩余进度。它可能配置第三方服务、运行一次性迁移，或将项目从一个状态转移到另一个状态。

[template.sh](template.sh) 已提供了令人愉悦的 UX——带剩余时间的进度条、确认关卡、跨平台 URL 打开（包括 WSL）、隐藏式密钥输入、幂等的 `.env` 写入、`gh secret`/`gh variable` 写入以及结束摘要。**你的工作仅是确定流程范围并编写其阶段。** `STAGES` 标记上方的库在每个向导中都是相同的；这种一致性正是关键所在——永远不要手动编辑它。

向导默认是临时的——为单次运行而构建，保存到 scratch 或 `scripts/` 路径，任务完成后即删除。仅当用户想要一个可重复的设置路径且该路径应保留在仓库中时，才提交它。

## 流程

### 1. 确定流程范围

梳理人类必须采取的每个手动步骤以及过程中捕获的每个值。首先阅读仓库——不要一上来就问：

- 对于设置：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置以及 `.github/workflows/*`（每个 `secrets.*`/`vars.*` 引用都是向导必须产出的值）。
- 对于迁移或转换：当前状态、目标状态以及它们之间的不可逆操作。

然后向用户展示按顺序排列的阶段列表以及每个阶段产出的值，并确认——他们可以添加、删除或重新排序。

**完成标志：** 每个阶段已按顺序命名，并且对于每个捕获的值，你都知道 (a) 人类从哪里获取它，(b) 它写入哪里（`.env`、GitHub 密钥、两者都写，或都不写——有些阶段只是纯操作），以及 (c) 它是保密（隐藏输入）还是公开的。

### 2. 映射每个阶段的旅程

对于每个阶段，编写人类要遵循的精确路径：打开哪个 URL，在那里做什么，值显示在哪里，它填充哪个变量——例如"控制面板 → 开发者 → API 密钥 → 显示测试密钥 → 复制"。如果你不确定当前 UI 或确切的命令，请说明情况并询问用户或查阅文档——切勿编造可能不存在的步骤。

**完成标志：** 每个阶段都能追溯到陌生人也能够遵循的具体说明。

### 3. 编写向导

将 `template.sh` 复制到目标路径。将示例阶段替换为每个步骤一个 `stage`，按依赖顺序排列。使用库辅助工具——`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`——并将 `TOTAL_STAGES` 和 `TOTAL_MINUTES` 设置为诚实的估计值（这将驱动剩余时间显示）。

保持模板设定的标准：在询问值之前先打开 URL，对任何保密内容使用 `ask_secret`，对每个持久化的值使用 `write_env`，仅对 CI 实际需要的值使用 `set_secret`，在任何不可逆操作之前使用 `confirm`。每个 `stage` 会清除屏幕，使当前步骤唯一可见——保持一个阶段只做一项聚焦的任务，以免用户需要的信息滚出屏幕。不要触碰标记上方的库。

### 4. 验证并移交

- `bash -n <script>`；如果可用，运行 `shellcheck`。
- `chmod +x <script>`。
- 不要自己从头运行到底——它会打开浏览器并阻塞等待人工输入。改为静态追溯：步骤 1 中的每个值都被捕获并落到了步骤 1 指定的位置，且每个 `set_secret` 名称与 CI 中的 `secrets.*` 引用完全匹配。
- 告知用户如何运行它。如果是可重复的设置路径，提交它并在 README 中添加链接，以便下一个人直接运行脚本，而不是询问 AI。
