一个模糊的构想出现了——太大，单个 agent 会话装不下，而且笼罩在迷雾中：从这里到**目的地**的路径尚不可见。Wayfinding 就是找到那条路，而不是冲向目的地。本技能将路径规划为仓库问题跟踪器上的一个**共享地图**，然后处理其**决策工单**——其解决方案是一个决策，而不是要执行构建的切片——一次一个，直到路线清晰。

目的地因任务而异，命名它是制图的第一步——它塑造每个工单。它可能是一份要交接并迭代的规范、一个在规划开始前要锁定的决策，或者一个就地进行的变更，如数据结构迁移。地图与领域无关——工程工作、课程内容，任何适合的形态都可以。

## 规划，而非执行

Wayfinder 默认为**规划**：每个工单解决一个决策，当路径清晰时地图就完成了——在某人去执行之前没有剩下任何需要决策的事情。直接去做的冲动通常是已经到达地图边缘、该交接的信号。任务可以在其**备注**中覆盖此默认行为——将执行带入地图本身——但除此之外，产出决策而非交付物。

## 按名称引用

每个地图和工单都是一个议题，因此它有一个**名称**——它的标题。在人类阅读的所有内容中——叙述、地图的"已做出的决策"部分——都通过该名称引用它，绝不要使用裸的 ID、编号或短标识。一堆 `#42, #43, #44` 难以阅读；名称一目了然。ID 和 URL 不会消失——名称包裹着其链接——但它们位于名称_内部_，不会替代它。

## 地图

地图是此仓库问题跟踪器上的单个议题，标记为 `wayfinder:map`——规范的产物。其工单是地图的子议题。

地图是一个**索引**，而非存储。它列出已做出的决策并指向持有其细节的工单；一个决策恰好存在于一个地方——它的工单中——因此地图从不复述它，只摘要和链接。

**地图、其子工单、阻塞关系和前沿查询具体存放的位置取决于跟踪器。** 问题跟踪器应该已经提供给你——如果没有，请运行 `/setup-matt-pocock-skills`。查阅跟踪器文档的"寻路操作"部分，了解_此_仓库如何表达它们。如果未提供跟踪器，则默认使用本地 Markdown 跟踪器。

### 地图正文

整个地图以低分辨率加载，每个会话一次。打开的工单**不会**列出——它们是通过查询找到的开放子议题。

```markdown
## 目的地

<到达此地图末尾的样子——此任务正在寻找其路径的规范、决策或变更。一到两行；每个会话在选择工单前都会参考它。>

## 备注

<领域；每个会话应查阅的技能；此任务的常设偏好>

## 已做出的决策

<!-- 索引——每个已关闭工单一行：足以判断相关性，然后点击链接查看工单持有的细节 -->

- [<已关闭工单标题>](链接) — <答案的一行摘要>

## 尚未明确

<!-- 参见"战争迷雾"：在范围内的迷雾，你还不能提开工单；随着前沿推进而毕业 -->
```

### 工单

每个工单是地图的一个**子议题**；跟踪器的议题 ID 是其身份。其正文是问题，大小适合一个 100K token 的 agent 会话：

```markdown
## 问题

<此工单解决的决策或调查>
```

每个工单带有一个 `wayfinder:<type>` 标签——`research`、`prototype`、`grilling`、`task` 之一（参见[工单类型](#work-through-the-map)）。

一个会话通过将工单分配给驱动地图的开发人员来**认领**它，**首先**，在任何工作之前，以便并发会话跳过它。该负责人_就是_认领：一个开放、未分配的工单是未被认领的。

阻塞使用跟踪器的**原生**依赖关系——这至关重要，因为它在跟踪器自己的 UI 中*可视地*呈现前沿，因此人类无需打开地图即可看到哪些可取用。只有缺乏原生阻塞功能的跟踪器才会回退到正文约定。当一个工单的所有阻塞工单都已关闭时，它被视为**未阻塞**；**前沿**是开放的、未阻塞的、未认领的子工单——已知的边缘。

答案不是正文的一部分——它在解决时记录（参见[处理地图](#work-through-the-map)）。解决工单时创建的资产从议题链接，而不是粘贴进去。

## 工单类型

每个工单要么是 **HITL**——人在循环中，与_能代表自己的人_一起工作——要么是 **AFK**，由 agent 单独驱动。HITL 工单只能通过实时交流来解决；agent 绝不能替代人类一方（回答自己问题的追问 agent 已经违反此规则）。

- **Research（研究）**（AFK）：阅读文档、第三方 API 或知识库等本地资源，以揭示决策所依赖的事实。由 `/research` **子 agent** 解决。当需要当前工作目录之外的知识时使用。
- **Prototype（原型）**（HITL）：通过制作一个廉价、粗糙、具体的产物来提升讨论的保真度——大纲、粗略草案、桩代码，或通过 /prototype 技能的 UI/逻辑代码。将原型链接为资产。当"应该长什么样"或"应该怎么表现"是关键问题时使用。
- **Grilling（追问）**（HITL）：对话。默认情况。始终调用 /grilling 和 /domain-modeling 技能。
- **Task（任务）**（HITL 或 AFK）：在做出_决策_之前必须完成的手动工作——没有需要决策、原型或研究的内容，但讨论被阻塞直到完成。注册服务以便评估其 API、配置访问权限、移动数据以便看到其形态。这是唯一一种_执行_而非决策的类型——它通过解除决策的阻塞来获得自己的位置，而不是通过交付目的地。agent 在其能力范围内自行驱动（AFK）；否则它交给人类一个精确的清单（HITL）。工作完成后即解决；答案记录完成的内容以及后续工单依赖的任何结果事实（凭证位置、新 URL、行数）。

## 战争迷雾

地图是_故意_不完整的：不要绘制你还看不到的东西。在活跃工单之外是**战争迷雾**——你预感即将到来但尚无法确定的问题和调查的模糊视图，因为它们依赖于仍开放的问题。解决一个工单会清除其前方的迷雾，将任何现在可明确的内容升级为新的工单——一次一个，直到通往目的地的路径清晰，没有剩余工单。

地图的**尚未明确**部分就是记录该模糊视图的地方：怀疑的问题、以后需要重新审视的区域。它是_朝向_目的地的未被发现的前沿——这里的所有内容都在范围内，只是不够清晰到可以开工单。根据视野允许的程度写得松散或完整；它同时为合作者阅读任务方向提供了路标。

**迷雾还是工单？** 检验标准是你现在能否精确陈述问题——_不是_你现在能否回答它。

- **当问题已经清晰时开为工单**——即使它被阻塞，你还不能对其采取行动。
- **当尚未明确时**你还不能如此清晰地表述它。不要预先将迷雾切成工单大小的碎片：它比工单更粗糙，一片迷雾可能升级为多个工单，也可能没有一个，一旦前沿到达它。

**尚未明确**排除了已经决定的（已做出的决策）、已经是活跃工单的，以及不在范围内的（下一节）。

## 不在范围内

迷雾只会_朝向_目的地汇集。目的地确定了范围，因此超出它的工作**不在范围内**——它不是迷雾，也不属于**尚未明确**。它在地图上有自己的**不在范围内**部分：你有意识地排除在_此_任务之外的工作。范围，而非清晰度，将其放在这里。

不在范围内的工作永远不会升级——前沿在目的地处停止——因此它只有在目的地被重新绘制时才会返回，并且是作为新的任务，而非恢复。

将某事判定为不在范围内是一个划定范围的行为，而不是路线上的一个步骤。当一个已经存在的工单被发现位于目的地之外——在制图时错误地纳入，或由某个解决方案暴露——**关闭它**（已关闭的工单明确不在前沿上）并在**不在范围内**部分留下一行：要点加上为什么不在范围内，链接已关闭的工单。它不进入**已做出的决策**，后者记录实际走过的路线——范围边界不是路线上的一个步骤。

## 调用

两种模式。无论哪种方式，**每个会话决不解锁超过一个工单**——研究工单除外。

### 绘制地图

用户带着模糊的构想发起调用。

1. **命名目的地。** 运行一次 `/grilling` 和 `/domain-modeling` 会话，确定此地图正在寻找其路径的目标——规范、决策或变更。目的地确定范围，因此首先确定。
2. **绘制前沿。** 再次追问，这次是**广度优先**：在整个空间展开，而不是深入任何一个线程，揭示开放的决策和现在可采取的第一步。**如果这没有发现迷雾**——通往目的地的路径已经清晰，整个旅程小到可以在一个会话中完成——你不需要地图。停下来询问用户希望如何继续。
3. **创建地图**（标签 `wayfinder:map`）：填写目的地和备注，"已做出的决策"为空，将迷雾勾勒到**尚未明确**中。
4. **创建你现在可以明确的工单**作为地图的子议题——然后在**第二轮**中连接阻塞边（议题需要有 ID 才能相互引用）。连接将它们分类为前沿和被阻塞；你尚无法明确的所有内容留在迷雾中——**尚未明确**部分。
5. **启动研究子 agent。** 对于你刚创建的每个 `research` 工单，启动一个 `/research` 子 agent 并行解决它，将其发现捕获在一次性 `research/<name>` 分支上，并附上来自工单的上下文指针。
6. 停止——制图是一个会话的工作；它不亲自解决任何问题。

### 处理地图

用户以地图（URL 或编号）调用。可以选择一个工单**可选**——如果没有，你选择下一个决策，而非用户。

1. 加载**地图**——低分辨率视图，而不是每个工单的正文。
2. 选择工单。如果用户指定了一个，使用它。否则按顺序取第一个前沿工单。**认领它**：在任何工作之前将其分配给自己。
3. 解决它——**根据需要放大**：按需获取任何相关或已关闭工单的完整正文；调用 `## Notes` 块中命名的技能。如有疑问，使用 `/grilling` 和 `/domain-modeling`。
4. 记录解决方案：将答案发布为**解决方案评论**，**关闭**议题，并将**上下文指针追加**到地图的"已做出的决策"中。
5. 添加新浮现的工单（创建再连接）；将答案使其可明确的任何迷雾升级，从**尚未明确**中清除每个升级的片段，使其仅作为新工单存在。如果答案揭示一个工单——这个或其他——位于目的地之外，**判定其为不在范围内**，而不是在路线上解决它。如果决策使地图的其他部分无效，更新或删除这些工单。

用户可能并行运行未阻塞的工单，因此预期其他会话同时编辑跟踪器。
