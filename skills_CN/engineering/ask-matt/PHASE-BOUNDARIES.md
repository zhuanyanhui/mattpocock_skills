# 阶段边界

一个 **phase（阶段）** 是会话中的一块工作——审查、实现、QA。这个定义有意保持模糊：一个阶段在你想*"好吧，这部分搞定了"*时结束。

**阶段边界** 是两个阶段之间的间隙，而这个决定只属于这里。在阶段中间没有决定要做——继续，或将剩余的工作拆分为子 agent。在阶段中间压缩上下文会让 agent 丢失思路。

## 五个选项

| 选项 | 它做什么 |
| ------------ | --------------------------------------------------------------- |
| **Continue（继续）** | 留在会话中。完全没有上下文切换。 |
| **`/clear`** | 清空上下文窗口，从零开始。 |
| **`/handoff`** | 写一个可移植的 markdown 文件，并在任何地方用它播种一个会话。 |
| **Subagent（子 agent）** | 发送任务到它自己的上下文窗口，拿回一份报告。 |
| **`/compact`** | 压缩此上下文并用摘要播种一个新会话。 |

## 决策树

在边界处从上到下工作。第一个**是**即为答案。

**1. 你能在这个会话中继续吗？** 有两个条件让答案是肯定的：下一阶段需要此阶段作为**一手资料（primary source）**，或者你还有足够的 [smart zone（智能区）](https://www.aihero.dev/ai-coding-dictionary/smart-zone) 剩余（约 150k tokens）让下一阶段容纳进去。审查 → 实现是标准的"是"：实现需要逐字推理，而非摘要。Continue 零成本零损失，所以在任何其他选项之前先排除它。

**2. 此上下文对接下来的工作是否无关紧要？** 这个会话中的一切——探索、决策、死胡同——都是可丢弃的吗？如果是，执行 **`/clear`**。这是棋盘上最便宜的一步：不花时间，还回整个窗口。`/clear` 也不是终结性的——旧会话保持可恢复状态。

搞错这个决定的代价是单向的。清除了一个*相关*的上下文，你就丢失了所建之物背后的**为什么**，无论怎么把 diff 读回来都无法恢复。

**3. 你需要移交吗？** `/handoff` 的范围很窄。仅在以下情况需要：

- 换到**新工具**（Claude → Codex），
- 移到**新目录**或仓库，
- 将工作发送给**同事**，
- 或在阶段中间分叉一个你发现的旁支任务而不打断正在进行的工作。

这个列表就是完整条件。`/handoff` 买到的是**可移植性**——一个可以旅行的文件。如果没有东西在旅行，你不需要它。

**4. 这个任务可以 AFK（离开键盘）完成吗？** 它的范围是否足够收紧，可以在你离开键盘、不需要引导的情况下运行？那么把它发送给**子 agent**，保持此会话不受影响。自动化审查是标准案例：agent 读取 diff 并报告，你在它工作时不需要参与。

**5. 否则，`/compact`。** 相关上下文、相同工具、相同目录，且你需要保持在循环中——这就是决策树的终点，而且经常落在这里。给它一个指令（`/compact 我们要对这个区域做 QA`），这样摘要会保留下一阶段需要的内容。

`/compact` 是**默认选项，而非首选**。它位于底部是因为上面的四个问题都更便宜或更精确。人们从这里开始的失败模式是：一个对摘要扁平化了的决定自信地犯错的新会话。

## 一手资料和二手资料

除了 **Continue** 之外的每个操作都把**一手资料**变成了**二手资料**——正在发生的会话，被它的摘要所取代。这个权衡总是同样的形状：

| 来源 | 信息 | 噪音 | 操作空间 |
| --------------------------------- | ----------- | ----- | ------------ |
| 一手资料（Continue） | 完整 | 很多 | 很小 |
| 二手资料（`/compact`、`/handoff`） | 有损 | 较少 | 很大 |

这就是为什么问题 1 排在第一位。你只在停留的成本超过节省时才付出有损的代价。

## 这些是判断调用

这些问题不是客观的——每个都带有品味，同一个边界在两天可能走向不同。价值在于**按顺序**问这些问题，在边界处而非工作中间。
