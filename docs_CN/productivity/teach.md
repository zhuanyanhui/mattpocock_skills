## 它做什么

`teach` 将你运行它所在的目录变成一个常驻的教学工作区，并在许多[会话](https://www.aihero.dev/ai-coding-dictionary/session)中围绕一个主题教授你，每次都是简短、自包含的 HTML 课程。

它不会根据[模型](https://www.aihero.dev/ai-coding-dictionary/model)已有的知识来教学。[参数化知识](https://www.aihero.dev/ai-coding-dictionary/parametric-knowledge)被视为不可信的：在教学之前，它会去寻找高可信度的资源，将它们记录在 `RESOURCES.md` 中，并在每节课程中引用它们。另一个结构性事实是它是[有状态的](https://www.aihero.dev/ai-coding-dictionary/stateful)——学习任务、资源、课程以及你已学内容的记录都以文件形式存在于目录中，因此下一次会话会从这些文件接续，而不是依赖上一次对话的残留内容。

## 何时使用

你通过输入 `/teach` 来调用它——[agent](https://www.aihero.dev/ai-coding-dictionary/agent) 不会自行调用它。

当学习本身就是项目时使用它：一门语言、一个框架、你刚加入的代码库、瑜伽、着色器、某个认证考试。它不适合在会话中顺带解释一个概念。

| 你想要什么 | 应该用什么 |
| --- | --- |
| 在数周内学习一个主题，课程不断积累 | `teach` |
| 在当前会话中解释一个想法 | 直接在该会话中提问 |
| agent 上一条消息没讲清楚，需要换一种说法 | [wait-what](https://aihero.dev/skills-wait-what) |
| sharpen 你已有的思维，而非获取新材料 | [grill-me](https://aihero.dev/skills-grill-me) |
| 一个后台 agent 阅读[一手资料](https://www.aihero.dev/ai-coding-dictionary/primary-source)并给你留下一份带引用的文档 | [research](https://aihero.dev/skills-research) |
| 在审问过程中学到某个新东西，但不想打断[审问](https://www.aihero.dev/ai-coding-dictionary/grilling) | 用 [handoff](https://aihero.dev/skills-handoff) 转移到一个教学工作区，然后在那里用 `teach` |

## 前置条件

`teach` 构建的是一个目录而非单个文件，并且该 skill 假设每个工作区只处理一个学习任务——所以请在一个你乐意完全交给单一主题的地方运行它。把它放在你正在工作的项目之外：推荐使用一个独立的仓库，而不是全局的 `~/.learnings/` 文件夹或当前工作项目。专用仓库也使得课程可以被 commit，这也是团队之间共享课程的方式。

该目录中会积累以下内容：

| 路径 | 存放内容 |
| --- | --- |
| `MISSION.md` | 你为什么学习这个。其他所有内容都围绕它展开；如果它不存在，`teach` 做的第一件事就是访谈你直到它存在 |
| `RESOURCES.md` | 经过审核的教学资料来源，分为知识类和文化类（社区） |
| `lessons/*.html` | 编号课程——教学的主要单元 |
| `reference/*.html` | 压缩速查表、算法、词汇表：你实际会反复查阅的文档 |
| `learning-records/*.md` | ADR 风格的笔记，记录你已明确掌握的内容，用于决定下一步教什么 |
| `assets/*` | 可复用组件——首先是共享样式表——让课程看起来像一门统一的课程 |
| `NOTES.md` | 你声明的教学偏好 |

关于这个列表有两点诚实的说明。词汇表适合大多数主题，但该 skill 附带了一个 `GLOSSARY-FORMAT.md`，`SKILL.md` 已经不再链接它，所以除非你主动要求，否则不会生成词汇表（[issue #559](https://github.com/mattpocock/skills/issues/559)）。另外，工作区并不总是创建在你预期的位置——在基于它构建长期课程之前，先看看下面的第一个问题。

## 记忆保持力，而非流畅性

这里可以借用的概念是**记忆保持力**：长期记忆，与**流畅性**相对——流畅性是你在阅读时当场回忆的能力，感觉像是掌握了，但一周后就忘了。`teach` 通过理想难度来构建前者——提取练习、间隔练习、交错练习。知识学习先行，此时难度是敌人，因为它会消耗你理解所需的工作记忆；然后 skill 通过紧反馈循环进行训练，此时难度是工具。

有两个因素决定你被教什么。**学习任务**——具体的现实世界理由——为每节课程奠定基础；没有它，课程就会漂移得过于抽象，也无法决定下一步教什么。从学习任务和 `learning-records/` 出发，`teach` 会在你的**最近发展区**内选择下一节课程：足够有挑战性需要付出努力，但又不至于超出可学习范围。

这也是为什么该 skill 会提出质疑而非一味顺从。一个需要**智慧**——现实世界判断力——的问题会得到一个尝试性的回答，然后指向一个社区供你验证。测验是一个门槛而非形式：一位用户报告说说了"非常感谢"后被告知训练仍在继续。

## 课程、参考资料和组件

一节**课程**是一个自包含的 HTML 文件，短到一次可以完成，与学习任务挂钩，带来一个切实的收益。它会引用资料来源，推荐一份值得你自己去读的一手资料，并链接到姊妹课程和参考文档。

值得了解的一个区分：课程很少被重新查阅，参考文档则经常被查阅。因此，一节课程的压缩精华——语法表、算法、姿势序列、词汇表——应该放在 `reference/` 中，而不是埋藏在首次引入它的那节课程里。

课程由 `assets/` 中的**组件**构建：样式表、测验小部件、模拟器、图表辅助工具。复用是默认做法。agent 在撰写课程之前会先阅读 `assets/`，从已有的内容出发进行构建，而第二节课程可能用到的任何新内容都以组件形式编写而非内联。共享样式表是每个工作区获得的第一个组件；它正是防止输出变成一堆一次性作品的东西。

## 常见问题

**它把文件放在哪里？我的文件最终跑到了 `~/.claude/skills`。**

一个真实的、未修复的 bug（[#377](https://github.com/mattpocock/skills/issues/377)）。`SKILL.md` 对两种不同的根目录都使用了 `./`：`./MISSION-FORMAT.md` 及其兄弟文件确实与 `SKILL.md` 一起位于已安装的 skill 中，而 `./lessons/`、`./reference/`、`./learning-records/` 和 `./assets/` 应该位于你的目录中。一个 agent 如果针对 skill 的安装目录解析了第一种路径，就会继续把第二种路径也解析到那里，于是把你的课程写进了 skill 文件夹。在构建课程之前先检查第一节课程落在了哪里，在开始时明确指定目录，而不是依赖"当前目录"被正确理解。

**我是保持在一个会话中，还是每节课开一个新会话？**

三种方式都可以——保持在同一个会话中、在新会话中重新调用 `/teach`，或在同一目录中打开一个新会话。每节课程都是一次独立的调用。目录是连续性的载体，而非对话。常见的做法是在工作区中打开一个新会话，然后说 `/teach next lesson for <主题>`。

**我怎么知道它没有教我它编造的东西？**

仅凭 skill 的说法，你无法确定。你应该阅读一手资料。`teach` 还没有可靠到可以不经检验就信任，任何基于 LLM 构建的 skill 也是如此。 grounding 机制——`RESOURCES.md`、每节课程中的引用、每节课程推荐的一手资料——旨在让验证变得低成本，而不是消除验证的需要。这种失败并非假设性的：一位学习 2x2 魔方的用户被给出了不存在的还原步骤序列。此类情况的诊断检查清单是：模型、harness、投入程度——以及资料来源是什么。在带有精确记号的过程性领域风险最高，而在输出可立即验证的领域（比如你可以运行的代码）风险最低。

**正确的测验答案永远是第一个选项。**

Sonnet、Opus 和 GLM 上都有多人确认过，仍然未修复。`SKILL.md` 现在要求每个答案的单词数相同，这消除了另一个破绽——正确的答案曾经是唯一一个经过充分推理的选项——但对答案位置没有做任何规定。一位贡献者测试了一种指令级的修复方案并报告正确答案在九节课程中连续 33 次都落在 A 位置（[#335](https://github.com/mattpocock/skills/issues/335)），这表明 `assets/` 中一个在渲染时打乱顺序的测验组件才是真正的解决方案，而不是改进措辞。在该方案发布之前，请将答案位置视为毫无意义的。你的 `assets/` 目录是你自己的，可以随意修改，所以要求一个在渲染时打乱顺序的组件是一个合理的本地修复。

**它假设我已经知道了一些东西，使用了它从未定义过的术语。**

这是最常见的实质性投诉。没有评估步骤：`teach` 从学习任务和 `learning-records/` 中推断你的水平，而在第一次会话中不存在 `learning-records/`。一位在 wayfinder 管线中运行它的用户直白地指出——"它从未进行过审问来确定我的起点，所以对我已经知道什么做了很多假设。"另一位用户报告课程依赖于未定义的术语，还有一节针对其硬件定制的课程涵盖了硬件能做什么，却从未说过它不能做什么。两件事有帮助：在第一条消息中声明你已有的知识和你的盲区，以及当课程偏离你的水平时大声纠正，因为这种纠正会变成一条 `learning-records/` 记录并引导下一节课程。一个明确的知识评估步骤是一个长期存在的 feature request（[#725](https://github.com/mattpocock/skills/issues/725)），尚未实现。

**它有间隔重复功能吗？它知道什么时候停止教学吗？**

第一个问题的答案是没有，第二个问题的答案是不可靠。间隔和交错是课程设计时遵循的原则，但没有东西会安排复习计划，也没有 Anki 或日历集成——这两者都是反复出现的请求。相关的缺口是退出标准：正如一位用户所说，`teach`"擅长制作下一节课程，但不太擅长知道何时停下来切换到复习或实际练习。"如果你想要复习或训练而不是新材料，主动要求它；该 skill 不会自行提议切换。

**它只对代码有用吗？**

不是，非编码用途占了使用记录的更大部分：韩语、日语敬语、钢琴、吉他、桌游设计、OpenSCAD、电影情节、Azure 和 CCNA 认证考试、大学考试，以及八岁和十岁的孩子获得关于密室逃脱和火蝾螈的可打印书籍。该 skill 中没有任何东西是编程专用的——学习任务、资源、最近发展区和训练在任何领域都以同样的方式运作。在代码领域内，最强的报告用途不是从零开始学习一门语言，而是在不熟悉的代码库或新团队的技术栈中定位方向。

**我应该用什么模型来运行它？**

没有标准答案，报告的差异很大。更高的[推理努力](https://www.aihero.dev/ai-coding-dictionary/effort)被报告能产生明显比中等设置更好的课程。一位用户通过 Copilot CLI 配合 Codex 运行同一个 skill，只得到了一张 30 行的 HTML 卡片，而 Claude Code 则生成了一节完整的课程。它在 Claude Cowork 中可以不加修改地运行，取决于你的组织是否允许在那里添加 skill。如果课程输出很单薄，在重写你的 prompt 之前先更换模型、[harness](https://www.aihero.dev/ai-coding-dictionary/harness) 或推理努力程度。

## 它在正常工作时的表现

- 它在空目录中做的第一件事是访谈你为什么想学这个，而不是直接生成课程。
- `RESOURCES.md` 在课程之前被填满，并且每节课程都推荐一份值得你自己去读的一手资料。
- 课程中的主张都带有外部链接。没有引用的课程是 skill 在凭记忆教学。
- 一节课程一次会话就能完成，并让你能做一件你之前不会做的事情。
- 在目录中打开一个新会话然后说"下一节课程"会继续课程而不是重新开始。
- `learning-records/` 在增长，课程停止重复教授你已经掌握的内容。
- 课程看起来像一门统一的课程——它们引用 `assets/` 中的样式表，而不是各自携带自己的样式。
- 一个需要判断的问题会把你引向论坛、subreddit 或课程，而不仅仅是一个答案。

## 它的位置

`teach` 是一个**随时可用的独立 skill**。它不是构建链中的一个步骤，也不与工程流共享任何产出；它拥有自己的目录并在该主题持续期间一直存在。

它唯一的真正邻居是 [handoff](https://aihero.dev/skills-handoff)，通过 Matt 命名的组合作为"当我在被审问某个我不理解的东西时该怎么办？"的答案：不要在审问中途停下来学习——用 `/handoff` 转移到一个教学工作区，在那里用 `/teach` 学习，然后回来继续你离开的地方。附近的一个替代方案是 [research](https://aihero.dev/skills-research)，适用于你需要的是一份带引用的文档而非课程和记忆保持。当你不确定哪个 skill 或流程适合时，[ask-matt](https://aihero.dev/skills-ask-matt) 会在整个集合中为你指引方向。
