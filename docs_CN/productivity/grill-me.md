## 它做什么

`grill-me` 接收一个**模糊的构想**，通过访谈帮你理清思路，直到你能对它做出承诺。你不需要一个完善的计划才能开始——产生计划正是这个[会话](https://www.aihero.dev/ai-coding-dictionary/session)的目的。它以**轮次**提问：每一轮涵盖整个**前沿**——所有你已经解决了前置条件的问题——所以你永远不会被问到还依赖于尚未听到的答案的问题。

它是**[无状态](https://www.aihero.dev/ai-coding-dictionary/stateless)**的。它不写入任何文件，也不留下任何工作区。它留下的唯一东西是你自己头脑中一个更清晰的想法版本。

## 何时使用它

你通过输入 `/grill-me` 来调用它——[agent](https://www.aihero.dev/ai-coding-dictionary/agent) 不会自行调用它。在**全新的对话**中启动它，而不是在一个你已经让 agent 写好的计划之上。

一旦你有一个值得认真对待的想法——一个功能、一个产品方向、一个商业决策、一篇文章——就尽早使用它，远早于你理清它涉及什么的时候。模糊不是等待的理由；它正是这个会话要消化的东西。如果你已经能够精确地描述这个东西，你就不需要审视它了。

选择三个 grilling 技能中的哪一个取决于你面对的是什么：

- **任何事物，任何地方**——`grill-me`。它不需要仓库，不写入文件，主题也不一定是代码。
- **需要对齐的代码库**——[grill-with-docs](https://aihero.dev/skills-grill-with-docs)。同样的访谈，但是[有状态](https://www.aihero.dev/ai-coding-dictionary/stateful)的：它会读取你的代码，并把学到的东西记录在 `CONTEXT.md` 和 ADR 中。
- **一次会话装不下**——[wayfinder](https://aihero.dev/skills-wayfinder)。它将工作量绘制为一张地图，并在其中运行 grilling 会话。

保持[plan mode](https://www.aihero.dev/ai-coding-dictionary/agent-mode)关闭。Plan mode 会促使 agent 急于产出一个计划，这与保持探究状态恰恰相反。

## 这是一场对话，不是一次审问

技能提出问题，但**你**掌控范围。这是人们容易忽略的部分，它决定了一次会话是将想法转化为决策，还是产出自信的胡言乱语。

失败模式是**被动**——连续四十个问题都回答"同意，同意，同意"，最后得出一个 agent 写的、你点头附和的计划。它感觉很有成效，因为它很长。但实际上没有任何决策被真正做出，结果带着它不配得到的确定性。

主动意味着掌控方向。如果一个问题低于你需要的精确度，就反驳它。在范围偏离时指出来。回答"我不知道"并且是真不知道。这个技能是为了辅助工程师而构建的，不是取代工程师：最终产出的质量取决于你回答的质量，而不是提问的数量。

相反的错误是真实但更少见的——在访谈中停留太久，以至于永远写不到代码。

## 可审视和不可审视

有些问题可以通过讨论来回答。有些不能，再多的 grilling 也无法帮你到达那里。

"一个长表单还是三页？"和"这个交互应该是什么感觉？"是**不可审视的**——它们需要一些可以做出反应的东西。当你碰到这样的题时，停止 grilling。用 [prototype](https://aihero.dev/skills-prototype) 构建一个一次性版本，看看效果，然后回来用一句话回答。

试图通过讨论来解决一个不可审视的问题，是会话膨胀的根源。agent 不断地重新措辞，你不断地猜测，范围随着不确定性一起增长。

## 它正在工作的标志是

- 你不同意某个东西。一次没有任何来自你的反驳的会话，是你根本不需要的会话。
- 问题在几轮中到达，而不是一次漫长的滴注，并且后面的轮次明显建立在你之前所说的基础上。
- 你最终到达了一个你没预料到的地方，因为一个问题暴露了你一直在隐性做出的决策。
- 在结束时，你能向不在场的人为每个选择辩护。

## 常见问题

**我应该期待多少问题，以及我怎么知道它何时结束？**
数轮次，不要数问题。四轮四十六个问题是一个普通的会话。它在前沿为空时结束——每个分支都已访问过，没有什么被默默地假设。

**它问了我两百个问题。出了什么问题？**
通常范围太大了。让 agent 先把工作拆分成更小的部分，然后逐一审视。非常长的会话还会漂移到**[dumb zone](https://www.aihero.dev/ai-coding-dictionary/smart-zone)**，那里[上下文窗口](https://www.aihero.dev/ai-coding-dictionary/context-window)已经足够满，问题质量会下降。

**我可以回到一次只问一个问题吗？**
可以。在你的全局 `CLAUDE.md` 中添加：

```
When grilling, ask one question at a time.
```

**如果我确实不知道答案怎么办？**
说出来。"我不知道"是一个真正的回答，而你无法回答的问题通常是去 prototype 而不是猜测的信号。

**我在写规范之前需要开启一个新会话吗？**
不需要。会话的价值在于你刚刚构建的[上下文](https://www.aihero.dev/ai-coding-dictionary/context)。把同一个对话直接交给 [to-spec](https://aihero.dev/skills-to-spec)。

**模型重要吗？**
比大多数技能更重要。Grilling 依赖于[模型](https://www.aihero.dev/ai-coding-dictionary/model)自己对系统如何出错的直觉，所以给它你最好的那个。实现主要依赖上下文，可以容忍更便宜的模型。

## 它的位置

`grill-me` 是一个**可以在任何地方、对任何事物运行的独立技能**。无状态正是它可移植的原因：不需要仓库、不需要工作区、不需要设置，也不假设这个想法甚至与软件有关。人们用它来审视商业决策、写作、接下来该做什么——任何在他们头脑中定不下来的东西。

这种可移植性是与 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 的全部区别，后者运行同样的访谈，但会读取代码库来对齐，并将学到的东西记录为 `CONTEXT.md` 和 ADR。两者都建立在 [grilling](https://aihero.dev/skills-grilling) 原语之上；`grill-me` 是用户调用的前门，不携带任何东西。

如果你审视的东西确实是软件，你可以把同一个对话交给 [to-spec](https://aihero.dev/skills-to-spec)，然后继续进入构建流程——这是一个选项，不是技能的目的。当你不确定哪个流程适合时，[ask-matt](https://aihero.dev/skills-ask-matt) 会为你路由。
